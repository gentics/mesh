[[v1.6.19]]
== 1.6.19 (2022-02-14)

icon:plus[] Forms: The structure of providing options for a `selectgroup` has changed: the field is now called `options` and the fields of the elements must be `key` (the stored value) and `value` (the human-readable label). The old format of `listelements` with `value` and `label` fields is still allowed (and will be converted accordingly) but deprecated.

icon:plus[] Forms Helper: Changes the behavior of the `pollResultTemplate` helper to refer to the `generic.hbs` template for all elements except `checkbox` and `selectgroup`.

icon:plus[] Polls: Adds the labels of selectgroup values in the render context for poll results (under the key) `valueLabels`.

icon:plus[] Forms Helper: Adds the following new forms helpers:

* `getValueLabel KEY`: gets the label for the specified KEY for a selectgroup element. This is intended for rendering poll results, for example: `{{#each values}}{{getValueLabel @key}}: {{@value}}{{/each}}`.
* `formatDate DATE_STRING TARGET_FORMAT [SOURCE_FORMAT]`: parses the given `DATE_STRING` as a date in `SOURCE_FORMAT`, and returns the resulting string of formatting it in `TARGET_FORMAT`. When no `SOURCE_FORMAT` is specified, it is assumed to be an ISO date (YYYY-MM-DD).
* `formatTime TIME_STRING TARGET_FORMAT [SOURCE_FORMAT]`: parses the given `TIME_STRING` as a time in `SOURCE_FORMAT`, and returns the resulting string of formatting it in `TARGET_FORMAT`. When no `SOURCE_FORMAT` is specified, it is assumed to be an ISO time (HH:mm).

icon:plus[] Forms: Adds `valueLabel` for the selected items in a selectgroup when rendering e-mails with form data.

icon:plus[] Forms: Adds custom properties of a form element when rendering e-mails.

icon:plus[] Forms: Adds a mapping from element name to the element definition when rendering forms or form data.

icon:plus[] Forms: Adds custom element properties to render context for rendering poll results.

icon:plus[] Forms: Adds type of form (key: `type`) element when rendering form data for e-mails.

icon:plus[] Multipage forms: The new setting `multipageRenderMode` can be used to control which page will be marked as active. The following settings are available:

* `multipageRenderMode: SKIP_COMPLETED` (default): the first page, that is not marked as completed in the respective data node, will be marked as active for rendering
* `multipageRenderMode: FORCE_NEXT`: the page _after_ the last submitted page will be marked as active for rendering (even if that page is already marked as completed)

icon:plus[] Forms: Adds paging information for rendering the form progress:

* `form.pageCount`: the total number of form pages
* `form.currentPage.index`: the index of the currently active form page
* `form.currentPage.name`: the name of the currently active form page
* `form.currentPage.description`: the index of the currently active form page

icon:check[] Forms Helper: Fixes a possible NullPointerException in the `equals` helper.

icon:check[] Forms: Fixes an issue with the `templateContext` which was not used correctly for rendering.

icon:check[] Forms: Changes the path of the `forms-voted` cookie to /, since it is not only needed on the referer path (the page containing the poll), but also the API path for submitting new form data. This fixes the issue that two polls on the same page would overwrite the other polls cookie.
